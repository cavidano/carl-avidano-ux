Natura11y had grown across separate repositories for its core framework, React components, icons, and documentation. An update to the way I maintained it was long overdue. As I brought more <LinkOpenNew LinkUrl="https://bradfrost.com/blog/post/ai-and-design-systems/" LinkText="AI-assisted development" /> into my work, I wanted the tools to understand how those parts fit together.

That meant making the code easier to find and documenting the decisions behind the components.

## Bringing the pieces together

I brought Natura11y’s core framework, React components, icons, and documentation into a <LinkOpenNew LinkUrl="https://github.com/Natura11y/root" LinkText="monorepo" />—a single repository for related code and applications. This let me update a component, check its examples, and revise its documentation in the same workspace.

I removed a copied set of styles from the React development setup so HTML and React components could share the styles in Core. Storybook brought their examples into one workbench, where I could compare appearance and behavior.

The documentation needed attention too. I had built the original site with Gatsby, but maintaining it had become increasingly difficult. I found Astro much more intuitive and completed the bulk of the migration in just a few days, with support from AI.

## Giving AI tools the context they need

The monorepo was the starting point. I continued the work in Figma by adding component descriptions that explain how to use each component and the accessibility behavior to preserve.

For example, the Button guidance explains when to use a button for an action or a link for navigation. Icon-only buttons need an accessible name. Those details give AI tools something specific to follow when turning a design into code.

The Main Menu guidance explains which settings belong to Figma and how others map to React. A setting for previewing a small screen should not become an invented property in the code.

I also connected Figma variables to the CSS names used in Core. The repository records which source to follow when design and code disagree, with production code guiding accessibility and behavior. That is what I mean by AI-ready: giving the tools usable context for the decisions already built into the system.

## Result

Natura11y now gives me code, examples, and written guidance to draw on during AI-assisted work. I can point an AI tool to a component’s intended use and check its output against working examples. I’m still refining that context as the system changes.
