Natura11y has grown and evolved a lot over the years. An update to the way I maintained it was long overdue, and I knew it was time to bring everything together into one workspace.

I had originally set up separate repositories for the core vanilla framework, React components, icons, and documentation. As the system grew, keeping related changes consistent took more effort. I wanted a better way to work across those parts.

## A single centralized repository

I brought Natura11y’s core framework, React components, icons, and documentation into a <LinkOpenNew LinkUrl="https://github.com/Natura11y/root" LinkText="monorepo" />—a single repository for related code and applications. This let me update a component, check its examples, and revise its documentation in the same workspace.

I also wanted to prepare Natura11y for <LinkOpenNew LinkUrl="https://bradfrost.com/blog/post/ai-and-design-systems/" LinkText="AI-assisted development" />. My goal was to give AI tools the same examples and guidance I rely on when making changes.

The documentation needed attention too. I had built the original site with Gatsby, but maintaining it had become increasingly difficult. I found Astro much more intuitive and completed the bulk of the migration in just a few days, with support from AI. I also brought Storybook into the workspace so I could develop and review components alongside their documentation.

Within a <LinkOpenNew LinkUrl="https://bradfrost.com/blog/post/the-design-system-ecosystem/" LinkText="design system ecosystem" />, the code library, development workbench, and documentation each serve a different purpose, but need to work together.

## One source for shared styles

Core provides the shared styles and JavaScript used by Natura11y’s HTML components. The React package uses those same styles and some of Core’s reusable JavaScript functions. React handles its own component interactions. Icons contains the shared icon assets.

I removed a copied set of styles from the React development setup. React now gets those styles directly from Core, giving me one source to maintain.

Each package still has its own version and release. People can install the parts they need for their project.

## Reviewing components in Storybook

Storybook gives me a <LinkOpenNew LinkUrl="https://bradfrost.com/blog/post/a-frontend-workshop-environment/" LinkText="frontend workshop" /> where I can build and test components on their own. I connected the HTML and React examples so I can compare their appearance and behavior in one place.

That review includes accessibility. For example, I corrected the markup that tells screen readers which controls belong to a group of tabs. I made the change in both the HTML and React examples.

## Keeping documentation close to the code

The documentation lives in the same repository as the packages. I built the site with Astro, adding live component examples and guidance on typography, spacing, and themes.

## Result

Core, React, Icons, documentation, and Storybook now live in one workspace. Shared styles come from Core, and I can review component changes alongside their examples and documentation. I completed the bulk of the documentation’s move to Astro in just a few days.
