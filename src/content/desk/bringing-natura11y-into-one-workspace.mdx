This was a long-overdue update to Natura11y. I brought its Core, React, and Icons packages into one repository, built a new documentation site in Astro, and connected the HTML and React examples through Storybook.

Natura11y had grown across separate projects. Keeping its styles, component behavior, and examples aligned meant coordinating changes across those projects. I wanted one place to maintain the shared code and see how a change affected the different parts of the system.

## Giving shared code a clear home

A monorepo brings several related packages and applications into a single code repository. For Natura11y, that meant defining what each package owns and where the others should depend on it.

Core owns the shared styles, vanilla JavaScript behavior, and utilities. React uses those same styles and imports the utilities it needs, while managing its interactions through React. Icons remains a separate package for the icon assets.

One practical change was removing the copied framework Sass from the React development setup. With React using Core directly, a shared style has one source to maintain. The packages still have their own versions and releases, so people can install the parts they need.

## Reviewing HTML and React together

I moved Storybook into a shared application so I could work with HTML and React examples in the same environment. That gives me a place to compare how a component looks and behaves in each implementation.

I corrected tab semantics, dropdown accessibility attributes, and color contrast across the examples. For example, I updated the HTML and React tabs so the tab-list role sits on the navigation list. Reviewing both implementations together makes those relationships easier to inspect.

## Bringing documentation into the workflow

The Astro documentation site joined the same repository. I built out component guidance, live examples, and pages covering typography, spacing, and themes. Storybook supports component development and review; the documentation explains how to use the system.

The ongoing responsibility is keeping those pieces aligned. Having the source, examples, and documentation together gives me a practical way to review that work whenever a component changes.
