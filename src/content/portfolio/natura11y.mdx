## How it began

Natura11y is an open-source design ecosystem. It helps you design, build, and maintain inclusive user interfaces.

Natura11y began as a collection of artifacts from front-end development tutorials I was taking at the time. Designing for public services at NYC OTI motivated me to sharpen my front-end and digital accessibility skills.

Alongside my day job, I spent nights and weekends learning HTML, CSS, and JavaScript through online tutorials. I began applying lessons from these exercises to my own system.

Eventually, I had a large enough library, and Natura11y was born.

Natura11y allowed me to explore my own approach to building and customizing user interfaces. I saw a chance to create something of lasting value while continuing to learn and improve.

## Design ecosystem

Natura11y offers a modern design-to-code workflow. I call it a design ecosystem. Each part of the system supports the other parts and remains connected throughout the product design lifecycle.

The ecosystem includes:

- Figma (both a lo-fi and a hi-fi library)
- HTML, CSS (Sass), JavaScript, and React
- Icon library
- Webpack and Storybook

## Ecosystem architecture

I set up Natura11y as a monorepo. This brings its framework, React components, icons, documentation, and testing into one repository. I can now make a change and update the related parts in the same workspace. This helps me cut down on duplicate work and keep the parts in sync. Keeping the code and documentation together also gives AI tools clearer context.

I describe this work in more detail in [Moving the Natura11y design system into an AI-ready monorepo](/drawing-board/moving-the-natura11y-design-system-into-an-ai-ready-monorepo).

</TextBlock>

### Codebase

I aimed to keep the codebase minimal and maintainable. I've seen the effects that technical debt can have on an organization's ability to progress. Have you ever watched a team struggle for 45 minutes to add an icon to an existing system? I have, and it's not fun.

Kidding aside, technical debt is a serious matter, especially in the AI era. In my experience, Claude and Codex are indispensable support tools, but they cannot architect entire systems the same way a human can. I use AI every day, but stay in control of the architecture decisions. I carefully ensure everything stays grounded in best practices. This is important for maintenance and makes the process much more efficient in the long run.

</TextBlock>

### Components (vanilla and React)

I designed the HTML and React components to share Core’s stylesheet. Developers can use the same styles in vanilla JavaScript and React applications. This reduces duplication in a big way and makes maintenance easier. Both follow the same accessibility patterns, while React manages its own state and interactions. I use Storybook to develop and test both versions.

## Theme-based color system

I designed Natura11y’s color system around five themes: Primary, Secondary, Dark, Light, and Canvas. Themes can be customized, added to, or removed.

Each theme pairs its background with related text, border, link, confirmation, and warning colors. Applying a theme to a page, section, or component keeps those relationships together.

</TextBlock>

<FigureSingle width='medium' caption="Natura11y’s principal palette and correlated colors in the Figma library.">

<LightboxImage

/>

<TextBlock>

With Natura11y, you apply themes to entire pages or individual components. This is powerful because it removes the duplication usually needed to define themed components. For example, you can use the same button styles with primary, secondary, light, or dark themes.

Themes can be changed without changing a component’s structure. Themes can also be nested, so a light card can sit within a dark section and keep its own color relationships. Themes can be applied at specific breakpoints. This creates an intuitive way to apply color across different devices and screen sizes. Custom palettes still need contrast checks; the system provides a consistent way to define and apply them.

### Theme modes

I designed Natura11y to respect the viewer’s display preferences. It supports light and dark modes, can follow the system setting, and works with [forced colors mode](/drawing-board/preparing-natura11y-for-contrast-themes-a-k-a-forced-colors).

In the <LinkOpenNew LinkUrl="https://natura11y.github.io/root/packages/core/dist/html/examples/oceanic-pulse-newsroom/" LinkText="Oceanic Pulse example" />, backgrounds, text, borders, and links change together when the interface switches between light and dark mode.

</TextBlock>

## Typography

I kept Natura11y’s typography simple to make it easy to use and customize. Shared settings control font families, weights, line heights, and spacing. Headings and body text follow a consistent scale.

Two variables control that scale: the smallest font size and a multiplier for each step up. Changing them adjusts headings and body text together. Both variables can change at any breakpoint. This makes it easy to adjust typography for different screen sizes without tweaking each size separately.

The <LinkOpenNew LinkUrl="https://gonatura11y.com/type-scale/" LinkText="Type Scale Visualizer" /> lets you try different combinations and see the resulting sizes.

## Icon library

Natura11y includes its own icon library. The icon package is versioned independently. It includes the original vectors, which are also in the Figma libraries. Designers and developers can edit existing icons or create their own.

</TextBlock>

<FigureSingle>

![Depiction of the Natura11y icon detail page](../../images/natura11y/project-tour-icons.png)

<TextBlock>

I organized the icons as reusable Figma components. Each keeps the original vector artwork for editing and a named frame for SVG export. The icon package turns those SVGs into a font for the front end. This keeps the artwork consistent between design and code.

The <LinkOpenNew LinkUrl="https://gonatura11y.com/docs/icon/#managing-icons-with-figma" LinkText="Managing icons with Figma" /> guide explains the process.

## Figma UI kits

I created separate lo-fi and hi-fi Figma libraries that support different stages of a project. The lo-fi kit provides reusable patterns for exploring content, hierarchy, and flow. The hi-fi kit can then be customized into a project’s own design system, with its typography, colors, and component details.

</TextBlock>

<figure>

<figure>

<TextBlock>

Keeping the lo-fi kit separate lets me reuse it across projects and update it independently of their visual identities. It remains a shared tool for early design work, while each project’s hi-fi system develops around its specific needs.

The hi-fi kit connects shared design settings to Natura11y’s CSS variables. Theme modes match the color system. They don't need extra component variants, so designers and developers have a common reference.

</TextBlock>

AI has changed how we work. Natura11y continues to evolve with these new ways of working and the projects that use it. This includes all personal and Avidano Digital projects over the past few years.
